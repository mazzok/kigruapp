# Explorer Log 2 — Frontend admin section pattern

Date: 2026-07-22
Dispatched by: forge-design (mail-settings)

## Question (verbatim)
"Frontend admin section pattern — how is a new admin section built: component, routing, navigation, admin API service? Is there an existing Settings area? Form pattern?"

## Key observations (file:line)
- Angular 18.2 standalone + Material 18.2, `angular-oauth2-oidc` (`frontend/package.json:13-24`).
- Existing `settings/` area under adminGuard: routes `app.routes.ts:65-91` — `settings/organisation`, `settings/custom-fields`, `settings/permissions`. Nav links `app.component.html:37-48`. No single generic Settings component.
- Admin area `administration/` routes `app.routes.ts:17-64`, guarded `authGuard, adminGuard` (`core/guards/*.guard.ts`).
- Reference component (Board): `administration/board/board.component.ts` standalone, reactive `FormGroup`s, mat-tabs, save methods. Route `app.routes.ts:56-62`, nav `app.component.html:32-35`.
- API access: `core/services/api.service.ts` — `ApiService` wraps HttpClient, `baseUrl='/api/v1'` (`:7`), typed get/post/put/patch/delete. Feature services inject ApiService.
- Auth token: `core/interceptors/auth.interceptor.ts` adds `Authorization: Bearer` for `/api` (`:10-12`), registered `app.config.ts:18`.
- Forms: reactive forms everywhere; representative save `OrganisationComponent.addGroup()` (`settings/organisation/organisation.component.ts:140-171`); simplest `board.component.ts:236-243`. Shared dialogs: `shared/components/confirm-dialog`.

## Condensed answer
New mail settings page = standalone component under `settings/mail/`, route in `app.routes.ts` (adminGuard), nav link in `app.component.html` settings block, dedicated service via `ApiService`. Reactive form, follow OrganisationComponent/BoardComponent pattern.
