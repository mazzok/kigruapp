# Explorer Log 1 — Backend settings/config pattern

Date: 2026-07-22
Dispatched by: forge-design (mail-settings)

## Question (verbatim)
"Backend stack & settings/config storage — how does the backend store admin/global settings, what DB, what's the API/route/service pattern for a new admin resource? Secrets handling; jsonSchema validation mechanism."

## Key observations (file:line)
- Stack: Quarkus 3.36.1, Java 17 (`backend/pom.xml:10`), MongoDB via `quarkus-mongodb-panache`, Keycloak OIDC, Jackson REST. `com.networknt:json-schema-validator:1.5.6` (`pom.xml:73-77`). No `quarkus-mailer`, no scheduler.
- No route registry; JAX-RS `@Path` classes auto-discovered in `backend/src/main/java/at/kigruapp/resource/`, base `/api/v1`.
- Global config store: `entity/Organisation.java` (`@MongoEntity(collection="organisation")`, tag-based). Seeded tags "groups","duty-settings" in `migration/OrganisationSeedMigration.java:38-54`. Route `resource/OrganisationResource.java` GET/GET{tag}/PUT.
- Reference CRUD: `resource/FieldDefinitionResource.java` (list/get/create/update/soft-delete), entity `entity/FieldDefinition.java` (extends PanacheMongoEntity), validator `service/JsonSchemaValidatorService.java` (Draft V7).
- Auth: `security/SecurityFilter.java` ContainerRequestFilter, default-deny (line 96) → everything not whitelisted is admin-only. Admin check `security/CurrentUserService.isAdmin()` (`:77-97`).
- Secrets: `@ConfigProperty` from `application.properties`/env, e.g. `security/KeycloakUserService.java:15-25`. No `.env`, no DB-stored secrets. SMTP password in DB = new pattern.
- Startup hooks: `@Startup` + `@Observes StartupEvent` migration classes keyed by MIGRATION_ID.

## Condensed answer
New admin-managed settings resource: dedicated `@MongoEntity` singleton (or Organisation tag) + `resource/…Resource.java` modeled on FieldDefinitionResource; do NOT whitelist in SecurityFilter → auto admin-only. Secrets normally config-injected; DB-stored SMTP secret is a new pattern requiring explicit handling.
